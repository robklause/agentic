Setup & Install

Everything the series needs: Python 3.10+, VS Code, Ollama, three models, four pip packages, and a test PDF. One version trap in here produces a genuinely misleading error, so don't skip the Python section even if your machine "already has Python."

Builds on: nothing. This is the start. About 15 minutes of work plus model download time.

Python 3.10 or newer. Not optional.

The mcp SDK (used in Part 3) requires Python 3.10+. Many systems still ship 3.9.6 as the default python3.

The trap

pip install mcp on Python 3.9 doesn't say "your Python is too old." It says "No matching distribution found", which reads like a network problem or a typo. Check the interpreter before blaming the network.

python3 --version              # 3.9.x? install a newer Python first
python3.12 -m venv .venv
source .venv/bin/activate
python --version               # confirm 3.10+ inside the venv

VS Code

Any editor works; this series assumes VS Code with the Python extension, pointed at the venv above (Command Palette → "Python: Select Interpreter"). You'll spend a lot of time reading trace output next to code, and a split pane makes that comfortable.

Ollama

Ollama serves open-weight models on localhost:11434. Install from ollama.com, then confirm it's serving:

ollama serve   # "port in use" means it's already running — that's fine

The detail that makes the whole series work: Ollama exposes an OpenAI-compatible endpoint at /v1. The same openai SDK and tool-calling wire format that work against the cloud work unchanged against your laptop:

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
# api_key is required by the SDK but ignored by Ollama

The three models

Pull all three now; downloads are the slow part of setup.

ollama pull qwen3.5:9b               # chat model — the agent's brain
ollama pull nomic-embed-text         # embedding model — powers search
ollama pull granite4.1-guardian:8b   # guard model — input screening (optional)

If tool calling misbehaves

Not every local model supports tool calling well. If your model ignores tools or hallucinates arguments instead of emitting a proper tool_calls response, try a model documented as tool-call capable (gemma4:12b is a solid alternative) before debugging your code.

Hardware, and what to expect

This series was built on two machines that bracket the realistic range: a MacBook Pro with 16GB of RAM, and a workstation with 32GB of RAM plus a 16GB-VRAM GPU. Both run everything. Not at the same speed.

Ollama keeps a model in memory while it fits. The chat and guard models are each roughly 5-6GB at default quantization (approximate; varies by version). On 32GB with a GPU, everything stays resident. On 16GB, Ollama evicts one model to load another, and each swap costs seconds before the first token appears.

Takeaway

A long pause after a model switch is a stall, not a hang. Best performance comes from more RAM plus a dedicated GPU, APU, or NPU; Apple Silicon unified memory sits in the middle (use the -mlx tags); CPU-only with 16GB works and asks for patience. Relief valves: USE_LLM_GUARD = False drops the guard model from the rotation, and a smaller chat model is fine while learning the mechanics.

Python packages

Create requirements.txt with exactly this, then pip install -r requirements.txt inside the venv:

openai>=1.40.0
chromadb>=1.0.0
pypdf>=5.0.0
mcp>=2.0.0

openai is the client SDK (pointed at Ollama). chromadb is the vector database. pypdf extracts PDF text. mcp is the Model Context Protocol SDK, and it's the package that silently demands Python 3.10+.

The knowledge base PDF

From the Knowledge Base page onward, the agent searches a real document: a 58-page employee handbook for a fictional boutique, Marlow & Sage.

Download it here: Marlow_and_Sage_Handbook.pdf (92KB). Put it in the same directory as agentic_demo.py.

Any comprehensive, sectioned PDF of 40+ pages works as a substitute, but the examples, page citations, and calibration queries all assume this one, so using it keeps everything reproducible (see substitution notes if you swap). Toy three-paragraph examples hide every interesting retrieval problem, which is why the series uses a real document from the start.

Smoke test

from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")

response = client.chat.completions.create(
    model="qwen3.5:9b",   # or qwen3.5:9b-mlx if that's what you pulled
    messages=[{"role": "user", "content": "Reply with exactly: local stack is working"}],
)
print(response.choices[0].message.content)

A sentence back means the stack works and everything else is just code. Connection error: Ollama isn't running. Model not found: ollama list and compare the exact tag. More symptoms: Troubleshooting.
