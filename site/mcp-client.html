Merging Local and MCP Tools

The finished system: your agent discovers the weather server's tools at startup, merges them with local ones into a single list, and routes each call to a dict lookup or a wire protocol without the model knowing there's a difference. Four small changes to the loop, none of them control flow.

Builds on: the MCP server and the Part 2 agent. Full code: the final checkpoint.

The one real wrinkle: connection lifetime

The trap

The MCP client SDK is async and your file is synchronous. The lazy fix: keep run_agent sync and wrap each MCP call in asyncio.run(...). It runs. It also tears down the connection after every call, and for a stdio server the connection owns the subprocess. Every get_weather call spawns a fresh Python process, handshakes, makes one call, and kills it. The trace looks fine. The process table tells the truth.

The design

Open the connection once for the life of the run and thread it through. Same instinct as _kb_collection being a process-lifetime handle so Chroma isn't reconnected on every search. Concretely: run_agent becomes async def, and main opens one async with that everything runs inside.

The OpenAI SDK calls stay ordinary synchronous calls. They block the event loop during each model call, which is a non-issue for a single-user local demo and would be the opposite call for a service multiplexing conversations. Name the context, choose accordingly, write it down.

Discovery: schemas from the wire

MCP_SERVER_PARAMS = StdioServerParameters(command="python3", args=["mcp_weather_server.py"])


async def _discover_mcp_tools(mcp_client: Client) -> tuple:
    """Return (tool_schemas, tool_names) in the same shape TOOL_SCHEMAS uses."""
    discovered = await mcp_client.list_tools()
    schemas = [
        {"type": "function", "function": {
            "name": t.name,
            "description": t.description,
            "parameters": t.input_schema,
        }}
        for t in discovered.tools
    ]
    names = {t.name for t in discovered.tools}
    return schemas, names

The translation amounts to relabeling: list_tools() hands back name, description, and input_schema, and that schema is already JSON Schema, the same dialect you hand-wrote. Wrapping it in the {"type": "function", ...} envelope is the entire adaptation. That near-zero cost isn't luck; both sides standardized on JSON Schema, which is a large part of why the ecosystem could form.

The names set matters as much as the schemas: the model's tool_calls response carries only a tool name, with no hint where the tool lives, so the router needs its own memory of which names arrived via discovery.

Invocation: normalizing what comes back

async def _call_mcp_tool(mcp_client: Client, name: str, args: dict) -> dict:
    """Normalize the result into the same plain-dict shape local tools return."""
    result = await mcp_client.call_tool(name, args)
    if result.is_error:
        # An MCP tool that raises doesn't raise here — is_error is the signal.
        text = next((b.text for b in result.content if isinstance(b, TextContent)), "unknown error")
        return {"error": text}
    if result.structured_content is not None:
        return result.structured_content
    # No structured_content (see the gotcha on the server page): the text
    # block IS the JSON, so parse it rather than passing a raw JSON *string*
    # through as if it were a value.
    text = "\n".join(b.text for b in result.content if isinstance(b, TextContent))
    try:
        return json.loads(text)
    except (json.JSONDecodeError, ValueError):
        return {"result": text}

Three cases, one contract. Errors don't raise across the wire, so is_error becomes the same {"error": ...} dict your local tools have returned since calculate. Structured content is used when present. The fallback closes the server-page gotcha, with a final net for unparseable text.

Takeaway

Whatever happens on the wire, the loop sees the same plain dict it always has. Normalization at the boundary is what keeps the boundary invisible; anything that leaks past the adapter becomes a permanent tax on the core.

The loop: four small changes

1. Signature goes async and accepts the connection (all MCP params default to None, so a caller with no server still works, local-only):

    user_prompt: str,
    mcp_client: Client = None,
    mcp_tool_schemas: list = None,
    mcp_tool_names: set = None,
    max_turns: int = 5,
    verbose: bool = True,
    compact_after: int = 6,
) -> str:

2. The tool list the model sees becomes the merge:

        tools_for_this_turn = None if force_text_only else TOOL_SCHEMAS + (mcp_tool_schemas or [])

3. Dispatch becomes a router, at the exact seam marked back in Part 1:

            if mcp_tool_names and name in mcp_tool_names:
                result = await _call_mcp_tool(mcp_client, name, args)
                dispatch_via = "mcp"
            else:
                impl = TOOL_IMPLEMENTATIONS.get(name)
                result = impl(**args) if impl else {"error": f"unknown tool {name}"}
                dispatch_via = "local"

4. The verbose print gains a provenance label, so the trace shows what the model can't see:

                print(f"--- turn {turn}: executing tool ({dispatch_via}) ---")

That's the whole conversion. The guardrails around these lines are character-for-character what they were. The seam claim, kept.

Startup: one connection, everything inside it

async def main() -> None:
    ingest_pdf()
    calibrate_similarity_threshold()

    async with Client(stdio_client(MCP_SERVER_PARAMS)) as mcp_client:
        mcp_tool_schemas, mcp_tool_names = await _discover_mcp_tools(mcp_client)
        print(f"[mcp] connected — discovered tool(s): {sorted(mcp_tool_names)}")

        for p in prompts:
            answer = await run_agent(p, mcp_client=mcp_client,
                                     mcp_tool_schemas=mcp_tool_schemas,
                                     mcp_tool_names=mcp_tool_names)
            print(f"AGENT: {answer}")


if __name__ == "__main__":
    asyncio.run(main())

The async with block is the connection's lifetime: subprocess spawned and handshake spoken on entry, torn down on exit, every run threading through the one live client.

Run it

Startup now reads: ingest (or the skip line), the calibration table, then [mcp] connected — discovered tool(s): ['get_weather']. A tool your agent has never seen a schema for is in the model's list.

The prompt to savor is the whole series in one turn: "What's the weather in Austin, and is that temperature more than 3 times as warm as Seattle's?" It drives get_weather twice, dispatched (mcp) across a process boundary, then calculate for 3 × 68 (local), then compare for 101 against 204 (local), because the model was taught never to eyeball a magnitude judgment. Three tools, two sourcing mechanisms, one merged list, and the model treated them identically because from where it sits there's no difference to see.

What you built

Tools flowing from a local dict and from a real separate process over the actual wire protocol, indistinguishable to the model and to the rest of the agent loop, with every guardrail from Part 2 still in force.
