Calibrating a Similarity Threshold

Reject weak retrieval matches before the model sees them, with a threshold measured from a labeled eval set instead of guessed from two lucky examples. This page has the full calibration code, because "how do I pick a similarity cutoff" is probably what brought you here, and the answer is: you don't pick. You measure.

Builds on: the RAG agent. Full code: checkpoint chapter 7. Reproducing these scores needs the same PDF.

Why you don't guess

The tempting shortcut: run one good query and one bad query, eyeball the scores, split the difference. That's overfitting to two data points, and embedding geometry punishes it specifically.

The problem

When a document genuinely answers a query, the gap is often clean. When it has no answer, there's no "unrelated" score to fall back to, because in a topically coherent corpus everything is somewhat related. Every chunk of an employee handbook is about employment. In one real calibration of this system, "loss prevention" (an entire real section) scored 0.598 on its best chunk while "parental leave" (zero real content) scored 0.639. The absent topic outscored the present one. No single cutoff separates those two.

Your exact scores will differ; they're a property of document, chunking, and embedding model together. The overlap phenomenon is general. The response isn't despair, it's measurement: a threshold is a classifier, so calibrate it like one.

The eval set

Ten queries: five with confirmed answers in the handbook, five confirmed absent. Labels verified by grepping the extracted PDF text first, because an eval set labeled from what you assume the document covers calibrates to your assumptions, not your corpus.

EVAL_SET = [
    # Confirmed present in the handbook (grep'd the extracted PDF text first)
    ("How many PTO days do employees get?", True),
    ("What is the dress code policy?", True),
    ("What are the sales expectations for team members?", True),
    ("What is the loss prevention policy?", True),
    ("What are the store hours?", True),
    # Confirmed absent from the handbook (zero matches on grep)
    ("What is the company's policy on parental leave?", False),
    ("Does the company offer remote work?", False),
    ("What is the tuition reimbursement policy?", False),
    ("Does the company offer stock options?", False),
    ("Is there a gym membership benefit?", False),
]

Note what the negatives are not: random off-topic strings. "How do I fly a helicopter" scores low against any handbook and teaches the threshold nothing. These negatives are plausible HR questions, the hard cases that produce the generically-related score band. Calibrate on the boundary you'll actually defend.

The calibration function

SIMILARITY_THRESHOLD = None  # None = guardrail off


def calibrate_similarity_threshold(eval_set: list = EVAL_SET, verbose: bool = True) -> float:
    """Run each labeled (query, expect_match) pair through real retrieval,
    take the top-1 similarity score for each, and set SIMILARITY_THRESHOLD to
    the midpoint between the lowest true-match score and the highest
    true-non-match score — the biggest margin this eval set actually
    supports, not a number pulled from one lucky/unlucky example.
    """
    global SIMILARITY_THRESHOLD, _kb_collection
    if _kb_collection is None:
        _kb_collection = ingest_pdf()

    pos_scores, neg_scores, rows = [], [], []
    for query, expect_match in eval_set:
        result = _kb_collection.query(query_texts=[query], n_results=1, where={"type": "chunk"})
        top_sim = round(1 - result["distances"][0][0], 3)
        rows.append((query, expect_match, top_sim))
        (pos_scores if expect_match else neg_scores).append(top_sim)

    if pos_scores and neg_scores and min(pos_scores) > max(neg_scores):
        threshold = round((min(pos_scores) + max(neg_scores)) / 2, 3)
    else:
        # No clean separation in this eval set — the classes overlap, so any
        # single threshold will misclassify something. Fall back to the
        # midpoint of the overall score range rather than pretending a clean
        # cutoff exists.
        all_scores = pos_scores + neg_scores
        threshold = round((min(all_scores) + max(all_scores)) / 2, 3) if all_scores else 0.6

    SIMILARITY_THRESHOLD = threshold

    if verbose:
        print(f"\n--- calibrating similarity threshold from {len(eval_set)} labeled queries ---")
        for query, expect_match, score in rows:
            label = "match   " if expect_match else "no-match"
            predicted = "match" if score >= threshold else "no-match"
            flag = "" if (score >= threshold) == expect_match else "  <-- MISCLASSIFIED at this threshold"
            print(f"    expected={label}  sim={score:.3f}  predicted={predicted}{flag}  {query!r}")
        if pos_scores:
            print(f"    lowest true-match score:      {min(pos_scores):.3f}")
        if neg_scores:
            print(f"    highest true-non-match score: {max(neg_scores):.3f}")
        print(f"    calibrated threshold: {threshold:.3f}")

    return threshold

Three decisions to read closely. It scores through the real pipeline (real collection, real embedding function); calibrating against anything else measures a system you don't run. The happy path takes the midpoint of the actual margin the data demonstrated, not a round number that feels right. And the unhappy path refuses to lie: when classes overlap, no threshold is clean, so it falls back to the overall midpoint and prints every misclassification instead of manufacturing false precision.

What a healthy run looks like (from a real run of this system; your scores will differ):

--- calibrating similarity threshold from 10 labeled queries ---
    expected=match     sim=0.378  predicted=match  'How many PTO days do employees get?'
    ...
    expected=no-match  sim=0.269  predicted=no-match  "What is the company's policy on parental leave?"
    ...
    lowest true-match score:      0.290
    highest true-non-match score: 0.269
    calibrated threshold: 0.279

All ten classified correctly, but look at the margin: 0.021. Clean and razor-thin. Ten queries is a starting point; keep adding real queries and recalibrating as they accumulate. The verbose table is the difference between "calibrated" as an inspectable claim and as a vibe.

Enforcing it

In search_knowledge_base, the bare return {"results": results} becomes:

    if SIMILARITY_THRESHOLD is not None:
        kept = [r for r in results if r["similarity"] >= SIMILARITY_THRESHOLD]
        if not kept:
            return {
                "results": [],
                "note": (
                    f"no chunk met the calibrated similarity threshold "
                    f"({SIMILARITY_THRESHOLD:.3f}); best score was "
                    f"{results[0]['similarity']:.3f} — likely not covered in this document"
                ),
            }
        results = kept

    return {"results": results}
The design

The rejection message is engineered, not incidental. It tells the model what the bar was, how close the best miss came, and offers the hypothesis "likely not covered in this document." A tool that can say no, and here's why is doing work that otherwise lands on the model's judgment.

Run the parental leave question now: one below-threshold rejection, and the model says the handbook doesn't cover it. Mostly. Sometimes it takes that clear rejection and searches again, and again, and that interaction between two individually-correct guardrails is the next page.
