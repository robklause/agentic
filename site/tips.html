Tips & Lessons Learned

The whole series compressed for re-reading. Every entry is a standalone takeaway with a link to the page that earned it, written to still be useful a year from now on a system that looks nothing like this one.

Builds on: nothing. Bookmark this page. Jump to: model behavior · guardrails · retrieval · engineering practice

On model behavior

"Not mentioned" is not "confirmed no." The most dangerous RAG failure isn't invention from nowhere; it's the model converting a document's silence into a stated negative. It looks grounded, the retrieval happened, the citation is real, and the claim is manufactured. (Why guardrails)

A prompt fix built from one example teaches the example, not the rule. Ban one unstated negative and the model finds a neighboring one. State general rules as general rules, say explicitly they aren't limited to the example, and sketch the category space. Expect reduction, not elimination. (Why guardrails)

Audit what judgment remains after you delegate. A model given a calculator will compute 3 × 68 with the tool, then eyeball whether 101 exceeds 204 in its head. Every delegation has a residue. Finding and removing it, one judgment at a time, is what all these guardrails have in common. (First tools)

Bigger models lower failure rates and eliminate no failure modes. Their rarer failures arrive more fluent, which makes them harder to catch by eye exactly as rising trust makes everyone look less carefully. Model quality and guardrails are multiplicative, not substitutes. (Bigger models)

On guardrails

Prompts are requests. Code is a guarantee. The design test for every reliability rule: if the model ignored this sentence, what catches it? If nothing, you have a request where you need a structure. The strongest structures don't detect the bad choice, they remove it from the menu. (Why guardrails, backstops)

What you can check syntactically, fix with code; what requires judging meaning, a prompt can only make less frequent. Cited page in the retrieved set: code. Similarity above threshold: code. Two empty searches: code. "Is this a reasonable inference or a fabrication": prompt, plus honesty about the residual rate. This one principle sorts nearly every reliability decision you'll face. (Why guardrails)

A guardrail that prints "passed" may have verified nothing. A citation checker passes an answer with zero citations. For every check you build, ask what makes it vacuously pass, and either close that path or flag it separately. (Verifying citations)

Prefer precise-about-narrow over mushy-about-broad. Citation verification checks set membership exactly and says nothing about paraphrase faithfulness, deliberately, because a faithfulness checker would false-positive on honest restatements and teach you to ignore it. Trustworthiness is the entire product of a guardrail. (Verifying citations)

Test guardrails together, not just alone. Two individually correct layers composed into an infinite search loop. Component tests validate components; the failures live in the interactions. Keep designed probe inputs for each layer in your standard run. (Guardrails that compose)

A guardrail can look validated by luck. The termination backstop appeared to work while a junk chunk quietly prevented it from ever firing. When a protection "works," ask whether you've seen it fire for the reason you think it fires. (Junk chunks)

A backstop keyed to a specific signal has a blind spot the failure can dodge; pair it with an unconditional bound. The empty-search counter never advances when reformulated queries keep matching semi-relevant chunks, so it can count correctly forever while turns burn. The countermeasure triggers on turn number alone: the last turn is always an answer turn. When termination matters, at least one layer should fire on count or time, not on a condition. (Backstops)

Calibrate thresholds from labeled data scored by the real pipeline; never eyeball them. Embedding similarity has no natural "no match" score: in a coherent corpus, an absent topic can outscore a present one. Build a small eval set, verify labels against the actual corpus, make the negatives plausible questions, and print the classification table with misclassifications flagged. (Calibrating a threshold)

Keep a written ledger of what your guardrails don't catch. This system ships with a known gap: a fabricated number with zero tool calls and zero citations passes every layer. Documented, reasoned, chosen. That's what separates a system whose risks are decided from one whose risks are discovered by users. (The known gap)

LLM-as-judge is a different layer, not a better one. A guard model understands intent a regex can't, and costs latency, nondeterminism, and a new attack surface, since the judge itself reads attacker text. Layer by economics: free deterministic checks first, model judge on what clears them. Decide fail-open versus fail-closed deliberately, in writing. (Input screening)

On retrieval

Embed documents and queries with the same function, structurally. Two embedding models means two vector spaces and meaningless distances, and nothing errors: scores still look like numbers. Route both sides through one piece of code so the mistake is hard to write. (Knowledge base)

Very short chunks are a correctness bug, not clutter. A two-or-three-word chunk scores inflated similarity against almost anything sharing common vocabulary (a bare "EMPLOYEE HANDBOOK" fragment hit 0.827 against an unrelated query). One junk chunk clearing your threshold can disarm guardrails layered far above it. (Junk chunks)

Key derived-data caches on the logic that derives, not just the source bytes. Change chunking rules without changing the PDF and a bytes-keyed cache serves stale chunks while you believe your fix is live. Fold a version constant into the hash and bump it with the logic. (The stale-cache trap)

On engineering practice

Tools return errors as data, never as exceptions. A raised exception kills your loop; an {"error": ...} dict goes back to the model, which can read it and recover. The tool boundary talks to a counterparty that can't catch. (First tools)

Schema descriptions are prompt engineering. Not documentation: behavioral instruction. The difference between a tool used correctly and ignored can live entirely in that string. Doubly true for MCP, where the server author writes the description steering your model. (Schemas, MCP server)

The docs describe the happy path; the running system defines the contract. An MCP tool returning a plain dict leaves structured_content as None, with the JSON hiding in a text block, which you only learn by calling a live server. Same lesson as confirming a guard model's output tag before trusting your parser. (The gotcha)

Open one connection for the life of the run, not per call. Wrapping each MCP dispatch in its own asyncio.run() works, and silently respawns the server subprocess on every tool call. Expensive handles are process-lifetime resources. (Connection lifetime)

Message lists have referential structure; edit them like it. Every tool result is paired by id to the assistant message that requested it, and a naive slice strands one half of the pair. Any history surgery must walk to a clean seam first. (Compaction)

Version mismatches surface as lies. pip install mcp on Python 3.9 says "no matching distribution," which reads like a network problem. When an install error makes no sense, check the interpreter before the network. (Setup)

Normalize at boundaries so the core stays ignorant. The MCP adapter converts every wire outcome into the same plain dict local tools return, which is why the loop never learned MCP exists. Anything that leaks past the adapter becomes a permanent tax on the core. (Normalization)

The trace is the product while you're building. Every design decision here came from reading raw request/response traces, and every guardrail announces itself in them. Verbose mode costs nothing and is the only way to know what your agent actually did, as opposed to what its final answer implies it did. (everywhere)

The one-sentence version

All of it

An agent is a loop; tools are its hands; guardrails are code holding every judgment the model shouldn't hold alone; MCP is a socket where the hands plug in.
