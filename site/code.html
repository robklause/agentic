Code Checkpoints

The complete, runnable state of the project at the end of every construction stage. Download a known-good file to start mid-sequence, or diff against one when your version drifts. Each checkpoint was produced by applying that stage's edits to the previous one, so consecutive files diff cleanly to show exactly what a stage changed.

Builds on: Setup for the environment each stage needs.

The knowledge base PDF

Marlow_and_Sage_Handbook.pdf (92KB, 58 pages) is the document every checkpoint from chapter 4 onward searches. Put it in the same directory as agentic_demo.py before running those.

It's a fictional employee handbook for a fictional boutique, written for this project: comprehensive enough to have real structure (18 sections, page-numbered, with the kind of cross-references and silences a real handbook has) and safe to publish because no real company's policies are in it. Using this exact file is what makes the calibration scores and page citations on these pages reproducible.

Substituting your own

Any comprehensive, sectioned PDF of 40+ pages works. Expect to change three things: KB_PDF_PATH, the running-header strip regex in _extract_pdf_pages (extract a page with pypdf and look at what boilerplate repeats), and the eval set, whose labels must be verified against your document. Then bump CHUNK_LOGIC_VERSION and recalibrate.

How to run a checkpoint

The code expects its real working filenames, so copy rather than run in place:

cp agentic-demo-chapter-07.py agentic_demo.py
python agentic_demo.py

For the two MCP stages, the server must also exist under its runtime name (the agent launches it as a subprocess by that exact filename):

cp agentic-demo-chapter-13.py agentic_demo.py
cp mcp-weather-server-chapter-12.py mcp_weather_server.py
python agentic_demo.py
