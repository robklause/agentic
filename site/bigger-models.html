What Bigger Models Change

"Wouldn't a better model make all that guardrail work unnecessary?" No, and the reasons are worth having crisp, because you'll be giving them in meetings for years. No code on this page.

Builds on: the complete guardrail stack. Pairs with: the three-line cloud swap.

What actually improves

Be fair to the question first. A frontier-scale cloud model genuinely improves things: fewer ignored instructions, fewer hallucinated qualifiers, better search phrasing, more reliable tool-call formatting, better citation-format adherence. Latency and context capacity improve too. And the swap is three lines: base URL, API key, model name. Everything you built rides along unchanged.

Every failure rate discussed on this site moves in the right direction. So why keep the guardrails?

The rates move. The modes don't.

Because a bigger model reduces every failure rate and eliminates no failure mode. Frontier models still hallucinate, still convert silence into stated negatives, still garnish grounded answers with unsupported qualifiers. Less often. Not never. And your guardrails aren't priced in "often": the citation check exists for the one answer in fifty with an invented page, and one-in-fifty at production volume is a daily event.

The less obvious effect

A better model's failures are harder to catch, not easier. A small model's hallucinations are often clumsy: odd phrasing, formatting drift, non sequiturs that snag a reviewer's eye. A frontier model's rare hallucination arrives polished, confident, wearing the same style as its hundred correct neighbors. The signal your reviewers used degrades exactly as rising trust makes everyone review less carefully.

Structural checks don't have that problem. _check_citation_grounding verifies set membership identically whether the answer came from a 9B model or the largest thing money rents. That indifference to fluency is precisely what makes it valuable when fluency stops being a tell.

The stakeholder answer

Model quality and guardrails aren't substitutes; they're multiplicative. The model sets the error rate; the guardrails determine what escaping errors can do. Upgrade the model to make flags rarer. Keep the guardrails so "rarer" never silently becomes "invisible."

It cuts the other way too: guardrails are what make the small model usable. An unguarded 9B agent is a liability; the guarded system is trustworthy enough to demo, precisely because its checkable failures get checked. Guardrails lower the model quality you need, which on this project's economics is the difference between free-on-your-laptop and metered.

The gap this system knowingly ships with

Part 2 closes with a disclosure rather than a triumph, because writing down what your guardrails don't catch is worth more than any individual guardrail.

The known gap

Ask a numeric question the agent decides to answer from pure training memory: no tool calls, no retrievals, no citations. A fabricated number sails through everything. Input guardrails screen for injection, not fabrication. The similarity threshold never fires because search was never called. The backstop counts empty searches; there were none. The citation check finds no unverified citations, and its zero-citation clause only triggers when something was retrieved. Every layer reports clean. The answer is invented.

The system prompt addresses this ("if you haven't called a tool for a number, leave it out") and by now you can name that instrument on sight: a request. The structural version would verify that numeric claims trace to tool results, and this system deliberately declined to build it. That's a defensible judgment, not an oversight: a model paraphrasing "10 days per year" as "ten days annually" false-positives any naive text match, so a trustworthy version means fragile matching that cries wolf or another model-as-judge layer with its own costs. For this threat profile, a documented gap beat a noisy guardrail.

The habit to keep

Maintain an explicit, current list of known gaps with reasoning. That's what separates a system whose risks are chosen from one whose risks are discovered by users. When a stakeholder asks "is it safe?", the strong answer isn't "yes." It's "here's what's checked, here's what isn't, and here's why we drew the line there."
