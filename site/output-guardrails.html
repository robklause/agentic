Verifying Citations

The loop stops taking the model's word for its citations: track which pages search actually returned, parse which pages the answer cites, compare sets. About forty lines, and the first time the system trusts code over the model about anything.

Builds on: the RAG agent with the hardened prompt. Full code: checkpoint chapter 6.

The gap being closed

The problem

The system prompt asks the model to cite sources. That's a request. If the model cites a page it never saw (from its training-data memory of what handbooks look like), nothing notices. A user reading "per p.23" can't tell whether page 23 was retrieved this conversation or invented this sentence.

Whether a cited page was actually retrieved is a syntactic question, and by the principle, syntactic questions get answered in code.

Track, parse, compare

def _extract_cited_pages(text: str) -> set:
    """Find 'p.NN' style page citations anywhere in text."""
    return {int(n) for n in re.findall(r"\bp\.\s*(\d+)\b", text)}


def _check_citation_grounding(answer: str, retrieved_pages: set) -> list:
    """Return any page numbers the answer cites that were never actually
    retrieved this conversation — a hallucinated or misremembered citation.
    """
    cited = _extract_cited_pages(answer)
    return sorted(cited - retrieved_pages)

The same extractor runs on both sides: on tool results to build the retrieved set (every result's source field carries its page), and on the final answer to build the cited set. When two things must agree, route them through one piece of code; it's the shared-embedding-function instinct again.

In run_agent: a retrieved_pages = set() before the loop, and after each search result lands, union in the pages from each result's source.

The trap inside the obvious version

The trap

Ask what makes the obvious check print "passed." An answer with zero citations passes: nothing cited, nothing to flag. An answer citing "Section 5.3" instead of "p.18" passes: the regex finds no p.NN, empty set, green light. In both cases the guardrail verified nothing and reported success. A pass that had nothing to verify is false confidence with good UX.

So the check gets a second clause: if real content was retrieved and the answer contains zero page citations, that's a flag too. The full exit block:

        # Case 1: model is done — it returned a normal text answer.
        if not message.tool_calls:
            if verbose:
                print(f"--- turn {turn}: no tool_calls -> final answer, loop ends ---")

            cited_pages = _extract_cited_pages(message.content or "")
            unverified = _check_citation_grounding(message.content or "", retrieved_pages)
            if unverified:
                print(
                    f"--- GUARDRAIL: answer cites page(s) {unverified} that were "
                    f"never retrieved this conversation (retrieved: {sorted(retrieved_pages) or 'none'}) ---"
                )
            elif retrieved_pages and not cited_pages:
                print(
                    f"--- GUARDRAIL: real content was retrieved (pages {sorted(retrieved_pages)}) "
                    f"but the answer contains zero page citations — cannot verify grounding ---"
                )
            elif verbose:
                print(f"--- GUARDRAIL: citation check passed (retrieved: {sorted(retrieved_pages) or 'none'}) ---")

            return message.content

The zero-citation clause needs a cooperating model: an answer must cite in a parseable format before the format can be verified. The system prompt gets strict, including the oddly specific clauses that turn out to be load-bearing:

Citation format is strict: every fact you state from the handbook —
including facts you're citing only to explain that they DON'T answer
the question — must be tagged inline with the literal page citation
exactly as it appears in the chunk's source field, e.g. 'p.17'.
Section numbers like 'Section 5.3' are not a substitute for the page
citation; include the page citation every time, even alongside a
section number.
The pattern

Prompt shapes the output; code verifies it. Section numbers are the natural way a model summarizes a handbook chunk, and they're unverifiable by a page-tracking guardrail, so the prompt bends the model toward the format the code can check.

Two design decisions worth defending

Flag, don't block. The guardrail prints a warning and returns the answer anyway; in this system a human reads the trace, and the right response to a flagged citation is scrutiny. A production variant might retry or route to review. What matters architecturally: detection exists and is code. The response policy is a separate, swappable decision.

Citations only, not every claim. A fuller guardrail would check whether numeric claims appear in retrieved text, but a model paraphrasing "10 days per year" as "ten days annually" would false-positive as ungrounded. Paraphrase faithfulness means judging meaning, which is the prompt layer's job. Citations are the highest-confidence syntactic signal available: consistently formatted, explicitly requested, exactly verifiable. A guardrail that's precise about something narrow beats one that's mushy about something broad, because you can trust the narrow one's output.

What it doesn't catch

Keep the ledger honest. A fabricated claim wearing a retrieved page number sails through: the page checks out, the sentence doesn't. And an answer built purely from training memory (zero tool calls, zero citations) passes, because the zero-citation clause only fires when something was retrieved. That second gap gets named and deliberately accepted on the bigger-models page. Writing down what a guardrail can't see is part of building it.
